Delegate work to your persistent implementation worker: it shares this machine and repository, carries its own shell and process state, and keeps its context across handoffs, so later messages continue the same worker rather than starting over. The `message` is the assignment, a correction or update to a running handoff, or the answer to a question it raised — a first call spawns the worker; a call while one is already running folds the message into the current handoff instead of queueing a second. `block` defaults to true and waits for the worker's report inside this call; with `block: false`, or if the wait is interrupted or times out, the handoff keeps running in the background and its report arrives later — wait for it with `{{readTool}}` through that tool's declared interface rather than polling or ending the turn early. Reports come back as concise evidence: what changed, what was verified, what remains.
